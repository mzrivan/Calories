# Принятые решения

- **Master changelog Liquibase в YAML**, сами миграции — formatted SQL (`db/changelog/sql/*.sql`). Spring Liquibase нужен один корневой файл, `include` подключает SQL.
- **Размерность эмбеддингов** задаётся один раз: `EMBEDDING_DIMENSIONS` → параметр Liquibase `${embeddingDimensions}` (`vector(N)`) и `app.llm.embedding-dimensions`. `EmbeddingDimensionCheck` сравнивает с `atttypmod` колонки при старте.
- **Пользователи**: whitelist в `ALLOWED_TELEGRAM_IDS`; запись в `app_user` создаётся при первом сообщении разрешённого id (имя из Telegram). Деактивация — только вручную SQL (`update app_user set active=false, deactivated_at=now()`); `ON CONFLICT DO NOTHING` не воскрешает деактивированного.
- **Иммутабельность `dish_version`** обеспечивает триггер (разрешено менять только `active`/`deactivated_at`), плюс триггер запрета `DELETE` на `app_user`, `dish_version`, `meal_entry`, `chat_message`.
- **Роли**: `calorie_owner` (миграции), `calorie_app` (приложение: select/insert/update, без delete). Создаются `scripts/db-init.sql`; грант-миграция срабатывает, если роль существует (`runOnChange`).
- **Рецепт**: LLM передаёт итог всего готового блюда + `cookedWeightG` (+ необязательно `rawWeightG` для проверки правдоподобия); на 100 г считает код. Для продукта значения сразу на 100 г.
- **Валидация**: «жёсткие» ошибки (отрицательные, нет веса готового) не принимаются никогда; «мягкие» (Атуотер, диапазоны, отношение веса) возвращаются LLM для исправления, после `max-validation-retries` (2) принимаются с `LOW` и пометкой в допущениях. Черновик блюда в любом случае требует подтверждения кнопкой.
- **Деактивация блюда** — по id версии. Актуальная версия = самая свежая активная с тем же `normalized_name`.
- **Правка черновика текстом** = новый вызов `save_dish`; старый ожидающий черновик получает статус `SUPERSEDED`.
- **Повтор запроса к LLM** при ошибках (429/5xx) делается только пока в этом ходе не было записей, чтобы не продублировать их.
- **Итоги дня** выводятся блоком от кода после любого хода, где менялись записи, и после `get_day_summary` за сегодня / `set_goal`.
- **Подтверждение/отмена кнопкой** обходит LLM (быстро, бесплатно); результат записывается в `chat_message`, чтобы агент знал о событии.
- **Поиск**: trgm по `greatest(similarity, word_similarity)`; GIN-индекс создан, но на таком объёме данных планировщик, вероятно, выберет seq scan — это нормально.
- Версии зависимостей: Spring Boot 3.4.5, LangChain4j 1.3.0, telegrambots 8.3.0.
